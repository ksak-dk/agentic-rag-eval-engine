# 双端协同开发协议（Web Gemini 架构师 + Antigravity 执行者）

## 1. 会话与环境约束
- **复用单一会话**：全程复用同一个 `browser-skill` Session 打开 `https://gemini.google.com/app`，确保所有多轮对话都在网页版 Gemini 的**同一个对话线程**中进行，保留完整上下文。
- **隔离分支**：开始修改任何代码前，先执行 `git status` 检查工作区，并切到独立特性分支（如 `git checkout -b auto/pair-dev-test`）。
- **人工接管（Human-in-the-loop）**：如果网页端弹出登录验证、CAPTCHA 或安全提示，立即暂停并提示用户手动处理，处理完毕后再继续。

## 2. 网页版 Gemini 专属交互优化规范（核心防卡死）
在通过 `browser-skill` 操作 `gemini.google.com` 时，必须严格遵守以下操作顺序：
1. **每次页面变化后重新获取快照**：发送消息或页面滚动后，旧的 DOM 元素编号（ref）会失效，必须重新读取页面结构后再执行点击或提取，严禁盲用旧编号。
2. **流式输出等待策略（防截断）**：点击发送后，网页版 Gemini 需要 5~30 秒生成回复。**严禁发送后立刻抓取文本**。必须轮询等待，直到页面上的“停止生成（Stop）”按钮消失、且最新一条回复下方出现完整操作栏（如“复制 / 重新生成”按钮）时，再提取内容。
3. **精简读取，防上下文爆炸**：提取回复时，只读取**最新一条模型回复区域**的文本内容，不要将整个网页的侧边栏历史记录全部读入上下文。
4. **单轮汇报压缩**：发回网页版 Gemini 的本地执行报告严格控制在 **400 字以内**，仅包含：`改动文件列表`、`核心 git diff`、`测试结果（通过数或核心报错前 25 行）`。
5. **严禁后台挂起并提前结束回合**：执行 `uv run pytest`、`uv run ruff`、`git` 或 `bsk` 命令时，必须前台同步等待执行完成并拿到完整输出，严禁将命令丢进 Background Task 后直接结束当前回合。
6. **强制禁用 Git 分页器**：所有 Git 查看类命令必须加上 `--no-pager` 参数（例如 `git --no-pager diff`、`git --no-pager log`），防止终端卡在分页交互界面。
7. **网页端会话断线自动恢复**：首轮向网页版 Gemini 发送消息后，立即记录当前对话线程的完整 URL（格式如 `https://gemini.google.com/app/<thread_id>`）。后续任何一轮如果 `bsk` 发送或同步命令报错（如退出码非 0），必须直接用 `bsk` 重新打开该线程 URL 继续对话，严禁新开空白对话导致架构师上下文丢失。

## 3. 自动开发循环（最大熔断上限：6 轮）

### 第 0 步：初始化架构师
打开 `https://gemini.google.com/app`（如需深度推理，可先切换至 Pro / Thinking 模型），发送以下首条指令，并在收到首轮响应后立即记录当前对话线程完整 URL（`https://gemini.google.com/app/<thread_id>`）以便断线重连：
> "你现在是项目 `agentic-rag-eval-engine` 的首席架构师与代码审查员。我是你的本地 IDE 执行 Agent（Antigravity）。
> 本次总目标是：【填入用户目标】。
> 协作规则：
> 1. 请勿一次性输出全部代码，只给出【第 1 步最精简、可验证的执行指令】。
> 2. 我执行并运行 `uv run pytest` 后会把 Diff 和测试结果发给你审查。
> 3. 如果尚未完成或测试报错，请给出下一步修改指令。
> 4. 如果所有目标均已完美达成且测试全绿，请在回复的最后一行单独输出：`[ALL_TASKS_COMPLETED]`。"

### 第 1~6 轮：执行 -> 验证 -> 汇报 -> 审查
必须在一个完整的执行周期内走完“修改 -> 验证 -> 回传网页端 -> 读取下一轮指令”，直到收到 `[ALL_TASKS_COMPLETED]` 或达到最大轮次熔断上限：
1. **等待并提取**网页版 Gemini 的最新指令（若发生会话超时/断线，立即用 `bsk` 重开已记录的线程 URL 恢复上下文）。
2. **终止判定与收尾规范**：若回复中包含 `[ALL_TASKS_COMPLETED]`，立即跳出循环并关闭 `browser-skill` 会话；随后自动运行一次 `git status`、`uv run ruff check .` 和 `uv run ruff format --check .`，并在最终汇报中附上本次改动摘要与验证结果（默认不自动 `git commit`，交由用户确认）。
3. **本地执行**：按指令修改代码或配置，并前台同步运行验证命令（如 `uv run pytest`，获取 Diff 时使用 `git --no-pager diff`）。
4. **回传汇报**：将压缩后的改动与测试结果填入网页版 Gemini 输入框并发送，进入下一轮。
5. **熔断保护**：若达到 6 轮仍未收到 `[ALL_TASKS_COMPLETED]`，停止循环并向用户汇报当前卡点与最新 Diff。
